# Forge Qbit QSPARX v0.1.1

> **Publication status: partial.** The signed tag, GitHub Release, GHCR image,
> checksums, SBOMs, attestations, and release-bound reviewer build were produced.
> Pages deployment was rejected because the `github-pages` environment permitted
> only branch `main`, not protected release tags. The tag and published artifacts
> remain immutable evidence; use `v0.1.2` for the complete corrective publication.

Forge Qbit QSPARX v0.1.1 is the corrective first-publication release of the
synthetic, evidence-first cryptographic mission twin. The protected `v0.1.0` tag
remains immutable evidence of a release workflow that failed during action setup;
that run created no GitHub Release, GHCR image, attestations, or Pages publication.
Version 0.1.1 corrects the invalid action pins and adds a PR-time provenance audit
that requires every external workflow SHA to be a Git commit in the repository
declared by its `uses:` reference.

The capabilities are unchanged: deterministic inventory, risk,
migration-planning, simulation, and evidence-manifest workflows through a Python
library, Typer CLI, FastAPI `/v1` API, and read-only static reviewer console. The
release supports CycloneDX 1.6/1.7 input and canonical CycloneDX 1.7 CBOM output.

The release container is built and loaded locally. It is blocked on unwaived high or critical vulnerabilities
and used to generate SPDX and CycloneDX SBOMs before any registry authentication
or push. Publication creates only
`ghcr.io/577industries/forge-qbit-qsparx:v0.1.1` and
`ghcr.io/577industries/forge-qbit-qsparx:sha-<full-source-sha>`; both remote tags
must resolve to the same immutable digest before attestations and reviewer
publication proceed. No `latest` tag is published.

## Verification

From a clean checkout of tag `v0.1.1`, run:

```bash
node --version  # requires v22+; CI/release pin v24
uv sync --frozen --extra dev
make verify
make benchmark-smoke
make audit
GITHUB_TOKEN="$(gh auth token)" uv run python scripts/check_workflow_action_pins.py
```

After downloading every release asset into one directory, verify its checksums:

```bash
sha256sum -c SHA256SUMS
```

The smoke benchmark is development evidence, not an acceptance result.

## Maturity and limitations

- Maturity: **TRL 4 target**.
- Validation state: **`not_started`**.
- Claim states are limited to **`background_implemented`** and
  **`measured_synthetic`**.
- All included mission and demo data is deterministic, fictional, unclassified,
  and non-CUI. SBOM and vulnerability artifacts are real point-in-time outputs
  of the release build.
- The project performs no active scanning, live remediation, or operational
  deployment.
- The release does not establish government adoption, accreditation,
  authorization to operate, operational performance, or representative
  environment compatibility.
- No included cryptographic module is claimed to be FIPS validated.
- The corpus is not sealed, the preregistered acceptance evaluation has not
  completed, and independent validation has not started.
- Six Python APK findings have exact, time-bounded container vulnerability waivers
  based on absent runtime execution paths. They remain visible in the scan
  evidence, are not claims that upstream is fixed, and expire on 2026-08-21.
- The million-observation generator exercise is not an ingest, query-latency,
  detector-accuracy, or acceptance result.
